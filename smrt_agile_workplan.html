security-adventure

→
smrt/game/
Validated JSON game data
→
smrt/engine/
Renderer + logic
1
Author in security-adventure
Narrative designers write rooms, hotspots, dialogue trees, and badge triggers in smrt-schema JSON. security-adventure is the single source of truth for all game content.
2
Validate on push (GitHub Action)
A CI job runs the schema validator on every commit to security-adventure. Broken JSON or missing required fields fail the build before they reach the engine.
3
Sync to smrt/game/
On successful validation, a workflow copies (or submodule-updates) the game data into smrt's game/ folder. Engine code never lives in security-adventure; content never lives in smrt engine.
4
Engine loads at runtime
smrt engine fetches game.json at startup, initialises the world, and hands control to the player. Smarty the Fox gets the current scene context injected into every Claude API call.
5
Badge state persists locally
Earned badges and game flags are stored in localStorage. No backend required for MVP. Leaderboard / LMS export is a post-MVP concern.
